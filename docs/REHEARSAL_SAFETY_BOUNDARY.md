# Rehearsal Safety Boundary

The platform is **not safety-certified.** This document records
the strict separation between the Phase 16 mission rehearsal
pipeline and the runtime safety authority.

## 1. What the rehearsal pipeline CAN do

* parse a mission request and build a deterministic plan;
* validate the plan against bounded-motion limits and the
  forbidden-pattern scan;
* hand the plan to the supervisor for an explicit
  approve / reject / needs-review decision;
* simulate the motion-event sequence inside a bounded state
  machine;
* produce replay + analytics + audit artefacts.

## 2. What the rehearsal pipeline MUST NOT do

| Forbidden                                              | Enforcement                                              |
|--------------------------------------------------------|----------------------------------------------------------|
| move a real robot                                      | no `rclpy`, no network, no subprocess imports             |
| publish to `/cmd_vel` (directly)                       | validator rejects; sanitizer scan rejects in source text |
| open a network socket                                  | AST-level test asserts no `socket` / `urllib.request`     |
| import a cloud LLM SDK                                 | AST-level test asserts no `openai` / `anthropic` / etc.   |
| execute user code                                      | reporter writes JSON / Markdown only                      |
| skip the supervisor                                    | state machine refuses to enter `rehearsing` without `approved` |
| skip the validator                                     | runtime always consumes the diagnostics list              |
| label rehearsal evidence as bag-backed                 | replay bridge hardcodes `bag_backed=False`                |
| claim safety supervisor approval for a real run        | the disclaimer + audit notes make the simulation-only origin explicit |
| produce probabilistic / AI-derived analytics           | analytics counters are deterministic integers only        |

## 3. Sanitizer + validator rules

The Phase 16 safety scan rejects:

* direct `/cmd_vel` references in `proposal_source` / `notes` /
  plan text (unless the sentence carries a descriptive `never` /
  `do not` / `must not` sentinel);
* `while True:` patterns in any input text;
* "disable / bypass safety / safety supervisor";
* "ignore safety";
* "ignore / override / disable e-stop";
* "restricted_corridor" / "forbidden_zone" entry attempts;
* "as fast as possible" / "max(imum) / full speed".

The validator additionally enforces:

* per-waypoint distance ≤ 25 m;
* per-waypoint speed ≤ 0.5 m/s;
* |angle| ≤ 720°;
* motion-bearing plans must end in a `stop` or `dock` waypoint;
* `/cmd_vel` is never in the requested topic list;
* `/cmd_vel_requested` is the only motion-bearing topic.

## 4. Supervisor authority

The supervisor is the only gate that can authorise the rehearsal
to enter `rehearsing`. Validator-rejected plans never reach the
supervisor; supervisor-rejected plans never reach the runtime.

The supervisor also marks plans whose risk band is `restricted`
as `needs_review` (a non-approval). Plans with risk band
`blocked` are auto-rejected.

## 5. Honesty rules

* No artefact in `mission-rehearsals/` represents a real robot
  run.
* No artefact in `mission-rehearsals/` is generated by a real LLM
  call.
* No artefact in `mission-rehearsals/` claims safety certification.
* A rehearsal whose `final_status` is `completed` is *eligible*
  for review by a developer or operator. It is not authorised to
  run on the robot.

## 6. Hardware integration

Phase 16 does not integrate with hardware. A future phase that
wants to drive a real robot must:

1. produce an ADR documenting the bridge between rehearsal output
   and real-robot mission runtime;
2. update `docs/FUTURE_DIGITAL_TWIN_DIRECTION.md`;
3. ensure the runtime safety supervisor (not the rehearsal
   supervisor) is the only path to actuator authority;
4. ensure replay artefacts on the real-robot side are labelled
   `bag_backed=True` only when real bag artefacts exist on disk
   (the rule introduced by Phase 13).
